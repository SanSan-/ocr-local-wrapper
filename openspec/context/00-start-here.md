# Начало работы

Единственный первый файл проектного контекста. Нормативные требования находятся только в OpenSpec.

1. Всегда: [продукт](01-product-context.md), [безопасность](05-security-and-compliance.md), [запреты](07-anti-patterns.md), [инженерная спецификация](../specs/engineering-governance/spec.md).
2. По задаче: [словарь](02-domain-glossary.md), [архитектура](03-architecture.md), [команды](04-engineering-standards.md), [качество](06-testing-and-quality.md), [OCR](../specs/image-ocr/spec.md), [веб](../specs/local-web/spec.md).
3. До изменения: [очередь](../changes/README.md); для причин и примеров — [ADR](ADR/README.md), [примеры](examples/README.md), [исправления контекста](failure-log.md).

При конфликте описания с проверенным кодом приоритет у кода. Сохраняй оригиналы и секреты; Git — только по прямому
запросу. Не считай документальный PASS запуском OCR и не превращай известный пробел в принятый план.

Всегда применяй [CTX-005…008](../specs/project-context/spec.md): событийную сводку, восстановление и дисциплину окна;
безопасность — SEC-CONTEXT-001…004. Методика аудита CTX-009 применяется только в явно согласованной области; фоновое
расписание требует отдельного запроса.
