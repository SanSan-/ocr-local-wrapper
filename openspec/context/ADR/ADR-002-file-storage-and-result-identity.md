# ADR-002: Файловое хранение и пригодность результата

**Статус:** принято.

## Контекст

Повторное распознавание не должно требовать тяжёлой модели, если пригодный результат уже сохранён.
При выборе разных моделей один текстовый файл не подтверждает, какими настройками он получен.

## Решение

Хранить результаты и сведения об их пригодности локально в файлах без отдельного сервиса хранения.
Повторно использовать результат только при совпадении входа, выбранной модели и параметров.
Существующий пользовательский текст сохраняется; его замена выполняется в явном режиме повторного распознавания.

## Альтернативы

- Принимать любой готовый текст за результат выбранной модели: происхождение и настройки неизвестны.
- База данных или отдельный сервис усложняют размещение простой локальной утилиты.
- Хеширование содержимого весов и транзакционная публикация дали бы более строгие гарантии;
  они не входят в текущий выбранный механизм.

## Последствия и пересмотр

Кеш может обходиться без загрузки весов, но метаданные не доказывают неизменность содержимого.
Замена весов по прежнему пути требует предусмотренного контрактом обновления результата и перезапуска процесса.
Прямая запись не гарантирует атомарное восстановление после сбоя; несколько процессов не образуют транзакцию.
Пересмотр нужен при изменении способа хранения, идентичности результата или требований к сохранности.

Профильные требования: [пригодность кеша](../../specs/image-ocr/spec.md#requirement-ocr-006-кеш-по-пути-и-метаданным),
[пользовательский TXT](../../specs/image-ocr/spec.md#requirement-ocr-007-существующий-txt-и-force)
и [границы записи](../../specs/image-ocr/spec.md#requirement-ocr-008-запись-и-границы-сохранности).
