# Дополнительные правила ocr-local

Обязательное локальное приложение [инженерной спецификации](../spec.md).
Здесь находятся источники настроек, рабочие команды и известные ограничения приложения.

## Локальные условия работы

- Новые комментарии, строки документации
  функций и сообщения журналов пишутся по-русски. Существующие сообщения меняются только по необходимости текущей задачи.
- При введении переменной окружения её имя и безопасный пример синхронизируются с пользовательской справкой
  и при необходимости с .env.example.

## Среда и команды

Источники текущих настроек:

| Область                     | Источник                                                                                                              |
|-----------------------------|-----------------------------------------------------------------------------------------------------------------------|
| Версия пакета               | [ocr_local.__version__](../../../../ocr_local/__init__.py); pyproject получает её динамически                         |
| Python и сборочный механизм | [pyproject.toml](../../../../pyproject.toml): Python >=3.14, setuptools и wheel                                       |
| Рабочие зависимости         | [requirements.txt](../../../../requirements.txt): прямые и транзитивные версии закреплены точно                       |
| Упаковка и pytest           | [pyproject.toml](../../../../pyproject.toml): dependencies=[] — упаковочная схема, не отсутствие рабочих зависимостей |

Сборочные зависимости не закреплены точными версиями. uv/lock и конфигурация Ruff не введены;
конфигурация анализа SonarQube в репозитории не закреплена.
Смена схемы зависимостей регулируется [ENG-001](../spec.md#requirement-eng-001-среда-и-зависимости).

### Подготовка среды

Команды выполняются из корня проекта в Windows PowerShell 5.1. Для новой среды пример использует установленный
Python 3.14 и средство запуска `py`; первая команда проверяет доступность выбранного интерпретатора.
Если `.venv` уже подготовлена, используйте её без повторного создания. После ненулевого кода завершения
устраните ошибку перед следующей командой.

```powershell
py -3.14 --version
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

Если `py` не находит установленный Python, задайте переменной `$python314` полный путь к его `python.exe`.
Вместо первых двух команд используйте `& $python314 --version` и `& $python314 -m venv .venv`.

Зависимости устанавливаются из сети; веса моделей готовятся отдельно по
[OCR-003](../../image-ocr/spec.md#requirement-ocr-003-местный-путь-и-автономная-загрузка).
При необходимости создайте `.env` по [.env.example](../../../../.env.example) в UTF-8 без BOM,
указав свои каталоги моделей; существующий файл настроек сохраняется.

### Запуск

Справка командной строки доступна без загрузки весов:

```powershell
.\.venv\Scripts\python.exe -B -m ocr_local --help
```

Пример распознавания использует изображение `sample.png` из корня и заранее подготовленный каталог
`models/GLM-OCR`. Результат записывается рядом с изображением; существующий TXT обрабатывается по
[OCR-007](../../image-ocr/spec.md#requirement-ocr-007-существующий-txt-и-force).

```powershell
.\.venv\Scripts\python.exe -B -m ocr_local --input .\sample.png --model glm-ocr --model-path .\models\GLM-OCR
```

Веб-интерфейс запускается командой ниже либо сценарием [run_web.ps1](../../../../run_web.ps1)
из той же среды. Адрес и ограничения доступа определены в [WEB-001](../../local-web/spec.md#requirement-web-001-локальный-запуск).

```powershell
.\.venv\Scripts\python.exe -B -m ocr_local.web
```

Другой порт и явный IPv6-адрес передаются одинаково серверу и проверке источника запросов:

```powershell
.\run_web.ps1 -Port 7862
.\run_web.ps1 -HostAddress "::1" -Port 7862
```

Это альтернативные запуски. Для второго адрес браузера — `http://[::1]:7862`.
У модуля Python доступны параметры `--host` и `--port`; `localhost`, сетевые адреса и `-Reload` у сценария
отклоняются до открытия слушателя. После перезапуска обновите главную страницу для нового cookie сеанса.

### Проверки

Обычные тесты без интеграционной проверки реальной модели:

```powershell
.\.venv\Scripts\python.exe -B -m pytest -m "not integration"
```

Клиентские регрессии и проверка синтаксиса выполняются установленным Node.js:

```powershell
node --test tests/test_web_client.mjs
node --check ocr_local/web/static/app.js
```

Интеграционный тест GLM-OCR и изоляция браузерной проверки определены [ENG-002](../spec.md#requirement-eng-002-сохранность-данных-и-изоляция-проверок).
Для отдельно разрешённого тяжёлого теста заранее подготовьте GLM-OCR. Тест выбирает каталог через
`OCR_MODEL_PATH`; `OCR_GLM_MODEL_PATH` его не заменяет. Пример явно задаёт каталог модели и восстанавливает
прежние значения окружения после проверки:

```powershell
$savedOcrModelPath = $env:OCR_MODEL_PATH
$savedRunGlmTest = $env:RUN_GLM_OCR_TEST
try {
    $env:OCR_MODEL_PATH = (Resolve-Path -LiteralPath '.\models\GLM-OCR' -ErrorAction Stop).Path
    $env:RUN_GLM_OCR_TEST = '1'
    .\.venv\Scripts\python.exe -B -m pytest -m integration
    if ($LASTEXITCODE -ne 0) { throw "Интеграционная проверка завершилась с кодом $LASTEXITCODE." }
} finally {
    $env:OCR_MODEL_PATH = $savedOcrModelPath
    $env:RUN_GLM_OCR_TEST = $savedRunGlmTest
}
```

Пропущенный тест (`skipped`) не подтверждает работу модели; причины пропуска видны при добавлении `-rs` к команде pytest.

## Границы продукта и известные ограничения

PDF, пакетная обработка, структурированные таблицы и внешние сервисы моделей не входят в текущие возможности.
Ограничения реализованных механизмов описаны один раз в их контрактах:

| Ограничение                                                        | Основной источник                      |
|--------------------------------------------------------------------|----------------------------------------|
| Идентичность кеша и замена весов по тому же пути                   | [OCR-006/011](../../image-ocr/spec.md) |
| Неатомарная запись TXT и JSON, отсутствие межпроцессной транзакции | [OCR-008](../../image-ocr/spec.md)     |
| Защита локального веб-запуска                                      | [WEB-001](../../local-web/spec.md)     |
| История задач и событий                                            | [WEB-004](../../local-web/spec.md)     |
| Приём тела, изображения, очереди и файловые квоты                  | [WEB-004/007](../../local-web/spec.md) |
| Публичные сведения и безопасная диагностика                       | [WEB-008](../../local-web/spec.md)     |

В текущей реализации сохраняются ограничения веб-интерфейса:

- [Подготовка загруженного изображения](../../../../ocr_local/web/uploads.py) выполняет запись и проверку изображения
  синхронно в цикле обработки веб-запросов. На время этих операций обработка других запросов и отправка SSE могут задерживаться.
- В [разметке страницы](../../../../ocr_local/web/static/index.html) у поля результата нет доступного имени для программ
  чтения с экрана. Зона выбора файла реализована через `label` без роли кнопки. Обработчики Enter и пробела позволяют
  выбирать файл с клавиатуры, но не задают роль элемента для вспомогательных технологий.

Этот перечень не создаёт очередь работ; принятый объём находится в [состоянии работы](../../../changes/README.md).

## Проверки реальных моделей

Рабочие способы для отдельно разрешённой проверки:

| Проверка                                                           | Метод и граница                                                                                                                                         |
|--------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|
| [verify_ocr_runtime.py](../../../../scripts/verify_ocr_runtime.py) | Обе модели, повтор и переключение на искусственном кириллическом изображении; совпадение текста оценивается отдельно                                    |
| [benchmark_ocr.py](../../../../scripts/benchmark_ocr.py)           | Загрузка и повторные распознавания искусственной страницы (по умолчанию три, число задаётся --runs); фиксируются настройки, хеш входа, тексты и времена |

Изоляция данных задана [ENG-002](../spec.md#requirement-eng-002-сохранность-данных-и-изоляция-проверок), а границы оценки качества — [ENG-003](../spec.md#requirement-eng-003-приёмка-качества-и-производительности-ocr).
