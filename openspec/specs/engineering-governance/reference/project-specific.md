# Дополнительные правила ocr-local

Обязательное локальное приложение [инженерной спецификации](../spec.md).
Здесь находятся источники настроек, рабочие команды и известные ограничения приложения.

## Локальные условия работы

- Новые комментарии, строки документации
  функций и сообщения журналов пишутся по-русски. Существующие сообщения меняются только по необходимости текущей задачи.
- При введении переменной окружения её имя и безопасный пример синхронизируются с пользовательской справкой
  и при необходимости с .env.example.

## Среда и команды

Источники текущих настроек:

| Область                     | Источник                                                                                                              |
|-----------------------------|-----------------------------------------------------------------------------------------------------------------------|
| Версия пакета               | [ocr_local.__version__](../../../../ocr_local/__init__.py); pyproject получает её динамически                         |
| Python и сборочный механизм | [pyproject.toml](../../../../pyproject.toml): Python >=3.14, setuptools и wheel                                       |
| Рабочие зависимости         | [requirements.txt](../../../../requirements.txt): прямые и транзитивные версии закреплены точно                       |
| Упаковка и pytest           | [pyproject.toml](../../../../pyproject.toml): dependencies=[] — упаковочная схема, не отсутствие рабочих зависимостей |

Сборочные зависимости не закреплены точными версиями. uv/lock, конфигурация Ruff и процесс Sonar не введены.
Смена схемы зависимостей регулируется [ENG-001](../spec.md#requirement-eng-001-среда-и-зависимости).

В подготовленной среде из корня:

```powershell
.\.venv\Scripts\python.exe -B -m pytest
.\.venv\Scripts\python.exe -m pip check
```

Интеграционный тест GLM-OCR и изоляция браузерной проверки определены [ENG-002](../spec.md#requirement-eng-002-сохранность-данных-и-изоляция-проверок).

Тяжёлый тест включается через RUN_GLM_OCR_TEST=1 и команду:

```powershell
.\.venv\Scripts\python.exe -B -m pytest -m integration
```

Рабочие входы: `python -m ocr_local`, `python -m ocr_local.web` и [run_web.ps1](../../../../run_web.ps1).
Команды проверок реальных моделей применяются при явно разрешённом запуске.

## Границы продукта и известные ограничения

PDF, пакетная обработка, структурированные таблицы и внешние сервисы моделей не входят в текущие возможности.
Ограничения реализованных механизмов описаны один раз в их контрактах:

| Ограничение                                                        | Основной источник                      |
|--------------------------------------------------------------------|----------------------------------------|
| Идентичность кеша и замена весов по тому же пути                   | [OCR-006/011](../../image-ocr/spec.md) |
| Неатомарная запись TXT и JSON, отсутствие межпроцессной транзакции | [OCR-008](../../image-ocr/spec.md)     |
| Защита локального веб-запуска                                      | [WEB-001](../../local-web/spec.md)     |
| История задач и событий                                            | [WEB-004](../../local-web/spec.md)     |

Дополнительные ограничения API: схема запроса не запрещает неизвестные поля явно, загрузка читает файл целиком
без отдельного предела размера. Источник: [web/app.py](../../../../ocr_local/web/app.py).

Открытое расхождение с [WEB-005](../../local-web/spec.md#requirement-web-005-представление-и-параметры):
при промпте только из пробелов клиент отправляет запрос загрузки. Сервер отклоняет параметры до сохранения
изображения, но требование отказа без запроса на клиенте не выполнено. Клиент проверяет обязательность заполнения
поля, а сервер — наличие непробельных символов. Источники:
[клиент](../../../../ocr_local/web/static/app.js), [правило профиля](../../../../ocr_local/model_profiles.py)
и [обработчик загрузки](../../../../ocr_local/web/app.py).

Этот перечень не создаёт очередь работ; принятый объём находится в [состоянии работы](../../../changes/README.md).

## Проверки реальных моделей

Рабочие способы для отдельно разрешённой проверки:

| Проверка                                                           | Метод и граница                                                                                                                                         |
|--------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|
| [verify_ocr_runtime.py](../../../../scripts/verify_ocr_runtime.py) | Обе модели, повтор и переключение на искусственном кириллическом изображении; совпадение текста оценивается отдельно                                    |
| [benchmark_ocr.py](../../../../scripts/benchmark_ocr.py)           | Загрузка и повторные распознавания искусственной страницы (по умолчанию три, число задаётся --runs); фиксируются настройки, хеш входа, тексты и времена |

Изоляция данных задана [ENG-002](../spec.md#requirement-eng-002-сохранность-данных-и-изоляция-проверок), а границы оценки качества — [ENG-003](../spec.md#requirement-eng-003-приёмка-качества-и-производительности-ocr).
