# Дополнительные правила ocr-local

Обязательно вместе с [общим Python-профилем](python-common.md). Явные инструкции задачи имеют приоритет.

## Рабочие правила

- Пиши по-русски: документация, комментарии, docstring и строки журналов. Не меняй текст существующих сообщений без
  необходимости текущей задачи; используй минимальные инструменты и точечные изменения.
- Перед каждой записью перечитай файл и проверь явную UTF-8 без BOM. Не выполняй временных перекодировок; изменение
  кодировки требует прямого подтверждения. Не используй Python/многострочный ввод без явно указанной кодировки.
- Соблюдай одну точку истины для файлов и структур. Перед добавлением ищи существующий код; общая логика и значения
  должны переиспользоваться. DRY/SOLID/KISS/YAGNI: одна ответственность, контракт абстракции, небольшие интерфейсы,
  зависимость от абстракций; 40–50 строк функции — ориентир ясности. Не реализуй несогласованную функциональность и
  удаляй ненужный код только в рамках доказанной замены.
- CLI и веб вызывают общий сервис; пользовательский результат не подменяется внутренними объектами модели. Исходные
  изображения и пользовательские результаты не служат временными файлами тестов.
- При новом параметре окружения синхронизируй его имя и безопасный пример в пользовательской справке и при необходимости
  .env.example; существующий локальный .env не публикуй. Значения локального .env не раскрываются и не заменяются без
  явного запроса.
- Принятые требования/активные задачи/доказательства веди в OpenSpec. README содержит пользовательское руководство,
  CHANGELOG — выполненные изменения. Синхронизируй изменённые термины, примеры, ADR и ссылки по объёму задачи.

## Версии и среда

Пакет `ocr_local.__version__` — 0.1.0; pyproject получает версию динамически. Python >=3.14. Зависимости закреплены
точно в requirements.txt, включая транзитивные; pyproject dependencies=[] является фактической упаковочной схемой, не
доказательством отсутствия рабочих зависимостей. Build-system: setuptools>=68 и wheel; сборочные зависимости не
закреплены точными версиями, runtime-зависимости закреплены точно.

Текущие основные версии: Torch 2.11.0+cu128, torchvision 0.26.0+cu128, Transformers 5.6.2, FastAPI 0.136.1. Полный
набор — requirements.txt. uv/lock, Ruff-конфиг и Sonar-процесс не введены автоматически. Модельный каталог и зависимости
задаются параметрами этого приложения.

Для выполнения из корня в подготовленной среде:

```powershell
.\.venv\Scripts\python.exe -B -m pytest
.\.venv\Scripts\python.exe -m pip check
```

Перед отчётом об изменении кода нужны применимые существующие тесты, доступный настроенный линтер и сборка/рабочий
прогон по задаче; причину провала устраняй самостоятельно в разрешённом объёме. Для новой неопределённой логики добавляй
осмысленную проверку, не копирующую реализацию.

Тяжёлый тест: `RUN_GLM_OCR_TEST=1`, затем `.\.venv\Scripts\python.exe -B -m pytest -m integration`. Его нельзя включать
для документальной проверки. Рабочие входы — `python -m ocr_local` и `python -m ocr_local.web`; штатный run_web.ps1
запускается только для разрешённой рабочей проверки.

## Фактические настройки и компоненты

| Область                   | Значение / источник                                                                                             |
|---------------------------|-----------------------------------------------------------------------------------------------------------------|
| Модель                    | GLM-OCR/PaddleOCR-VL-1.6; общий реестр профилей, OCR_MODEL_PATH, профильные пути и явный --model-path           |
| .env                      | Загружается из cwd без override окружения процесса                                                              |
| Prompt / токены / пиксели | GLM: Text Recognition:/8192/2007040; Paddle: OCR:/2048/1003520; проверка общим профилем                         |
| CPU                       | Без CUDA сразу CPU; повтор после GPU-ошибки разрешён только выбранной настройкой                                |
| CPU-default               | OcrOptions/CLI false, RecognizeRequest true                                                                     |
| GPU                       | Прямое размещение cuda:0, BF16/FP16, SDPA; INT8 явно, без скрытого CPU-offload; inference_mode/use_cache        |
| Модельные файлы           | config.json, model.safetensors, tokenizer.json; local_files_only=True                                           |
| Запись                    | Прямая Path.write_text UTF-8; атомарной транзакции нет                                                          |
| Кеш                       | Путь+size+mtime_ns+модель/path/prompt/лимиты/INT8; старые записи сохраняются, произвольный TXT не импортируется |
| Веб                       | 127.0.0.1:7861; uploads и отдельные профильные TXT; один поток, SSE; lazy model pool ёмкости 1                  |

Рабочие компоненты: `ocr_local/service.py`, `utils/io_utils.py`, `utils/output_cache.py`, `utils/model_utils.py`,
`utils/env_utils.py`, `models.py`, `cli.py`, `web/app.py`. Проверки: `tests/test_output_cache.py`, `test_io_utils.py`,
`test_model_utils.py`, `test_cli.py`, `test_web_app.py`, `test_ocr_text_image.py`.

## Известные ограничения — не принятая очередь

- Кеш учитывает модель/path/prompt/лимиты/INT8, но не хеш весов или полного изображения. После замены весов по тому же
  пути нужны перезапуск и force; совпадение size/mtime не доказывает неизменность входа.
- Запись TXT и JSON не атомарна и не защищена общей межпроцессной транзакцией. Отказ до записи модели не доказывает
  сохранность при прерванной записи.
- Привязка к loopback не включает Host/Origin/client middleware. RecognizeRequest не запрещает неизвестные поля явно;
  upload загружает всё содержимое без отдельного лимита.
- _jobs и очередь событий не имеют общей политики ограничения/сохранения; только log_lines ограничен 250. Нет
  подтверждённого восстановления по снимку после разрыва SSE/перезапуска.
- Слот освобождается при ошибке thread.start и в finally worker; logging настраивается в lifespan. Это не добавляет
  устойчивую очередь или восстановление после завершения процесса.
- Тесты не доказывают качество реальной модели, полный жизненный цикл GPU и устойчивость всех ошибок записи. Эти
  свойства не объявляются готовыми.

Любое устранение этих ограничений — кандидат для отдельного решения и change. Планирование улучшений выполняется
отдельными change. PDF, пакетная обработка, структурированные таблицы и другие серверы моделей не входят в текущие
возможности.

## Обязательные правила контекста

Обязательно применять [SEC-CONTEXT-001…004 и ENG-006](../spec.md), [CTX-005…008](../../project-context/spec.md). Сводка
создаётся автоматически по событиям; полный порядок навыков остаётся в SKILL.md. CTX-009 сохраняет методику фонового
аудита как opt-in по отдельному явному запросу. Автоматические сводки не дают разрешения на создание фонового
расписания.
