## Context

Мотивация: [proposal](proposal.md). Пользовательские изменения уже заменили старый INT8/offload-загрузчик на BF16/FP16 и
добавили preload в lifespan; baseline pytest: 17 PASS/1 RED. Native Transformers 5.6.2 поддерживает обе модели. Paddle
config содержит use_cache=false; image_processor.size существует, min_pixels — нет.

## Goals / Non-Goals

Goals: один источник defaults, переключение и корректный кеш, минимальная задержка повторного OCR, измерения до/после.
Non-Goals: новые среды/веса, compile, пакетный OCR, замена процесса пользователя, общий аудит безопасности. Полные
границы в proposal.

## Decisions

1. Реестр model_profiles задаёт GLM (Text Recognition:/8192/2007040, min12544), Paddle (OCR:/2048/1003520, min112896).
   GLM default пикселей снижен с native9633792; крупный мелкий текст может требовать увеличения. Это открытый параметр,
   не скрытая потеря качества. max_new_tokens является потолком, EOS завершает раньше.
2. OCR_MODEL_PATH определяет текущий профиль; отдельные OCR_GLM_MODEL_PATH/OCR_PADDLE_MODEL_PATH переопределяют пути
   выбранных профилей. Соседние каталоги позволяют использовать уже установленные модели без изменения .env. Явный
   --model-path сохраняет приоритет. Native classes с trust_remote_code=False.
3. Один lazy model pool под блокировкой, ключ path/INT8/CPU policy. Cache-first остаётся в run_ocr. При смене —
   отпускание объекта и очистка CUDA, затем загрузка. Preload всех моделей отвергнут: замедляет открытие UI, занимает
   память, ломает работу кеша без весов.
4. Direct device_map, BF16/FP16, SDPA и eval; inference_mode, use_cache=True, do_sample=False, num_beams=1. Нет
   torch.compile/статического кеша: длительный warmup и вариативная форма изображений. INT8 только явно: на 0.9B/10GiB
   экономия памяти не важнее задержки. Измерение подтвердит эффект; сейчас только гипотеза.
5. images_kwargs.size с shortest_edge из профиля и longest_edge из параметра; доступ к отсутствующему min_pixels не
   нужен. Исходные файлы не уменьшаются.
6. Кеш v2 в прежнем JSON, отдельные ключи path+SHA256 (профиль/path/prompt/лимиты/INT8). Прежние записи сохраняются. CLI
   защищает TXT, веб использует имя с отпечатком параметров. Импорт произвольного TXT отвергнут: неизвестно, какой
   моделью он получен.
7. Ошибки: min_pixels из журнала покрывается тестом совместимости; time уже импортирован, SSE-тест доказывает
   завершение. Убирается требование preload для worker. Ошибки загрузки сохраняют первичную причину; слот освобождается
   также при thread.start.
8. Метрики perf_counter, CUDA synchronize на границах стадий для реальных измерений. Вывод сообщает
   загрузку/подготовку/генерацию, токены, усечение. Глобальные настройки устройства/CPU threads не меняются.

## Risks / Trade-offs

- [Память сохраняется между запросами] → ёмкость pool 1 и освобождение при смене/завершении.
- [Ограничение пикселей снижает детализацию] → редактируемый параметр, измерения только на известном корпусе.
- [Новые ключи не используют старые результаты автоматически] → прежние записи/TXT сохранены, force явный.
- [CPU fallback медленный] → сохраняется явный флаг; метрики показывают устройство.
- [Предел генерации может обрезать текст] → предупреждение и возможность увеличить.
- [Модель заменена по прежнему пути] → force и перезапуск процесса; хеширование гигабайт весов на каждый запуск не
  применяется.

## Migration Plan

Изменения кода → узкие тесты → общий pytest/pip check/build → реальные GLM/Paddle и сравнение baseline → локальная
веб-проверка → синхронизация документации/дельт → архив. Зависимости не обновляются. Для rollback сохраняется исходный
срез затронутых файлов в evidence; пользовательский сервис не перезапускается самовольно.

## Итог приёмки

[acceptance](evidence/acceptance.md) фиксирует 4.61x для тёплого Paddle, проверку обеих моделей/веба и границы. Cold
load не имеет доказанного устойчивого ускорения; CPU threads1 и disable_mmap не включены. Кириллическое отклонение
Paddle воспроизводится на исходном коде; точное качество partial отделено от runtime PASS.
