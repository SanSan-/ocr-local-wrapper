## MODIFIED Requirements

### Requirement: WEB-003 Один активный запуск

Веб SHALL допускать одну активную задачу под блокировкой, присваивать случайный job_id и возвращать 409 для второго
старта. Рабочий поток MUST освобождать активный слот после успеха/отказа. Ошибка старта потока SHALL освобождать
резервирование и возвращать ошибку без зависшего слота.

#### Scenario: Один активный запуск

- **WHEN** во время активной задачи поступает второй recognize
- **THEN** новая задача не создаётся, API возвращает 409.

#### Scenario: Поток не стартовал

- **WHEN** создание рабочего потока закончилось ошибкой
- **THEN** слот освобождён, следующий запрос может начаться.

### Requirement: WEB-004 SSE и результат

SSE SHALL передавать log и терминальное done, keep-alive при ожидании; успешный done включает текст, пути,
cached/device/quantized, модель, параметры, времена стадий и признак достижения лимита. История строк журнала MUST
ограничиваться 250. Очередь событий и словарь задач остаются без общей политики сохранения; гарантированный повтор после
SSE-разрыва не заявляется.

#### Scenario: SSE и результат

- **WHEN** общий сервис вернул распознанный текст
- **THEN** клиент получает done/status=ok с моделью и измеренными временами; это не доказательство сохранения истории
  после перезапуска.

### Requirement: WEB-005 Представление и параметры

Интерфейс SHALL показывать изображение, текст, запуск, журнал, выбор модели, prompt, max_new_tokens, max_pixels, INT8 и
force. Выбор/перетаскивание/вставка сохраняются; во время активного запуска настройки и замена изображения блокируются.
При выборе модели MUST подставляться её defaults; явные последующие изменения пользователя передаются в запрос. Upload и
предварительный просмотр результата MUST возвращать только кеш соответствующих настроек. Смена настроек очищает прежнее
представление результата до проверки нового кеша, не запускает OCR. Неизвестный профиль/некорректные пределы SHALL
отклоняться до создания задачи.

#### Scenario: Переключение модели

- **WHEN** пользователь выбирает PaddleOCR-VL-1.6 после GLM-OCR
- **THEN** отображаются OCR:/2048/1003520 и результат только нового выбранного профиля либо пустое поле.

#### Scenario: Представление и параметры

- **WHEN** загружено изображение с совпавшим профильным кешем
- **THEN** текст подставляется без загрузки весов и без нового OCR.

## ADDED Requirements

### Requirement: WEB-006 Каталог без весов

API SHALL отдавать два профиля с defaults и доступностью локальных файлов. Веб-страница, health, каталог и upload MUST
работать без загрузки модели при старте процесса. Недоступная модель отображается явно; распознавание без совпавшего
кеша возвращает локальную ошибку.

#### Scenario: Нет установленных весов

- **WHEN** приложение запущено без модельных каталогов
- **THEN** страница и health доступны, каталог сообщает недоступность; автоматически веса не скачиваются.
