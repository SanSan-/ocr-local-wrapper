## Context

Мотивация и границы: [proposal.md](proposal.md). Дизайн нужен из-за расхождения пользовательского наблюдения и наличия
обработчика в текущем коде.

Подтверждено чтением 2026-09-20:

- В [app.js](../../../../ocr_local/web/static/app.js) есть глобальный `paste` и `getClipboardImage`. Изображение
  передаётся в общий `handleFile`.
- `paste` молча завершается при `state.busy` или `!state.ready`; `handleFile` дополнительно требует
  `settingsForm.reportValidity()`. Список моделей должен успешно загрузиться до вставки.
- Извлечение перебирает `clipboardData.items`, но завершает поиск на первом image-элементе с пустым `getAsFile()` или
  неподдержанным MIME, даже если дальше есть подходящий файл.
- В [index.html](../../../../ocr_local/web/static/index.html) нет подсказки Ctrl+V. В
  сохранённом [source-before.zip](../2026-09-20-select-ocr-model-and-optimize-inference/evidence/source-before.zip),
  entries `ocr_local/web/static/app.js` и `index.html`, вставка тоже существует и подсказки тоже нет. Прежняя версия
  писала отдельное сообщение о получении изображения из буфера; текущая оставляет только общий журнал загрузки.
- [test_web_app.py](../../../../tests/test_web_app.py) проверяет лишь присутствие строки `clipboardData`.
  Прежняя [браузерная приёмка](../2026-09-20-select-ocr-model-and-optimize-inference/evidence/browser.md) подтверждает
  file chooser, но не настоящий Ctrl+V.
- [upload_image](../../../../ocr_local/web/app.py) принимает файл с расширением и текущие settings, проверяет параметры
  до сохранения и возвращает профильный кеш. Новый серверный маршрут не нужен.

Гипотезы: пользовательский отказ может зависеть от готовности каталога, валидности формы, состава буфера или загруженной
браузером версии скрипта. Ни одна из этих причин пока не подтверждена как причина пользовательского случая; удаление
обработчика опровергнуто. Детальный разбор ограничен именно этими входами.

## Goals / Non-Goals

Цель дизайна — общий путь загрузки для Ctrl+V, выбора и перетаскивания, с понятным результатом допуска или отказа.
Контракт: [WEB-005](specs/local-web/spec.md).

Не добавлять чтение через `navigator.clipboard.read()`, кнопку с запросом разрешения, очередь отложенных вставок, новые
форматы, автосброс параметров или обход серверной валидации. Основание: прежнее поведение использует стандартное событие
paste и уже имеет общий upload.

## Decisions

1. **Использовать существующее событие paste и общий handleFile.** Проверять изображение во всём событии независимо от
   фокуса; извлекать первый доступный JPEG/PNG/WebP/BMP, пропуская неподдержанные или пустые элементы. Сохранять имя с
   расширением по MIME для серверного контракта. Альтернатива с отдельным upload/новым API создаёт дублирование без
   необходимости.
2. **Отделить изображение от обычного текста до отмены стандартной вставки.** Без подходящего изображения не вызывать
   `preventDefault`, не очищать результат и не отправлять запрос. При принятом изображении отменять вставку
   сопутствующего текста и отправлять ровно один файл. Не добавлять отдельный keydown для Ctrl+V: это создало бы риск
   двойной загрузки.
3. **Сохранить ограничения модели и операции.** До готовности каталога сообщать причину, сохраняя диагностированную
   ошибку каталога. При неверных параметрах показывать существующую валидацию и понятный статус; значения не менять. При
   занятом интерфейсе не заменять изображение и не перетирать состояние активной операции. После исправления
   параметров/готовности пользователь повторяет Ctrl+V; скрытой очереди нет.
4. **Добавить подсказку и восстановить обратную связь.** Область загрузки показывает Ctrl+V, принятие картинки
   отражается в существующем журнале. Это дополнение интерфейса: удаление прежней подсказки не доказано.
5. **Проверять наблюдаемые эффекты.** Небольшой тест клиентского поведения исполняет текущий app.js с управляемым
   DOM/clipboard и перехватом сетевых вызовов, без новых зависимостей и копии реализации. Проверяются число
   upload/recognize, параметры, предпросмотр, результат и отмена текстовой вставки. Отдельная браузерная проверка
   использует настоящий системный буфер и Ctrl+V на искусственном изображении. Синтетический dispatch события не
   заменяет эту приёмку.

Решения сохраняют [ADR-003](../../../context/ADR/ADR-003-local-upload-worker.md)
и [ADR-004](../../../context/ADR/ADR-004-model-profiles-and-runtime.md); отдельный ADR не нужен.

### Проверка и доказательства

| Сценарий                                              | Компонент / рабочий вход         | Проверка                                                                        | Будущее доказательство      |
|-------------------------------------------------------|----------------------------------|---------------------------------------------------------------------------------|-----------------------------|
| PNG через Ctrl+V, разные положения фокуса             | paste → handleFile → /api/upload | Тест события + реальный браузер; одна загрузка, предпросмотр, нет recognize     | evidence/acceptance.md      |
| GLM/Paddle и ручные параметры, совпавший кеш          | selectedSettings и upload        | Проверить отправленные settings и текст нужного профиля; оба каталожных профиля | evidence/acceptance.md      |
| Только текст, неподдержанный/пустой элемент перед PNG | getClipboardImage и paste        | Текст не отменяется; выбирается первый пригодный файл                           | evidence/acceptance.md      |
| Загрузка/OCR заняты, каталог не готов, форма неверна  | state, reportValidity, статус    | Нет нового upload/recognize; прежний вход и параметры сохранены                 | evidence/acceptance.md      |
| Выбор и drop                                          | Общий handleFile                 | Существующие способы ввода продолжают работать                                  | evidence/acceptance.md      |
| Структура документов                                  | OpenSpec                         | strict validate, ссылки, UTF-8 без BOM                                          | evidence/context-summary.md |

На этапе proposal клиентские тесты, браузер и OCR имеют статус NOT_RUN. При реализации реальный OCR/GPU не требуются для
доказательства приёма изображения; состояния busy и кеш проверяются изолированно, без весов.

## Risks / Trade-offs

- [Буфер браузера/ОС отличается от синтетического события] → отдельно проверить Ctrl+V с искусственным PNG; записать
  браузер, источник буфера и фокус. Недоступность такой проверки оставляет её NOT_RUN.
- [Текущий пользовательский отказ не воспроизведён] → сначала проверить свежую страницу, готовую форму и скриншот в
  буфере; сохранить фактические условия. Не объявлять одну из гипотез установленной причиной без воспроизведения.
- [Невалидный промпт блокирует upload] → сохранить текущий серверный контракт и объяснить отказ, не заменять
  пользовательские параметры defaults.
- [Устаревшие статические файлы] → при проверке сверить отдаваемый app.js с текущим файлом и обновить страницу;
  изменение общей политики кеширования вне объёма.
- [Подмена пользовательских данных при приёмке] → отдельный localhost-экземпляр, временные uploads/cache/log и
  синтетическое изображение; рабочий сервер не заменять.

## Migration Plan

Данные и зависимости не мигрируют. После реализации обновить статические файлы и страницу; если приложение работает из
установленного пакета, обновить пакет штатным способом. Откат ограничить изменёнными файлами интерфейса, сохранив
прежние архивы, входы, результаты и веса. До архива нужны отдельные результаты клиентских проверок и реальной вставки;
один OpenSpec PASS их не закрывает.
