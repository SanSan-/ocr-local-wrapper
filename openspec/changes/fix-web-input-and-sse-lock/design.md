## Context

Причины и область описаны в [предложении](proposal.md); контракт — в [дельте local-web](specs/local-web/spec.md).
Сохраняются общий сервис и владение задачами внутри веб-процесса по [ADR-001](../../context/ADR/ADR-001-shared-local-ocr.md)
и [ADR-003](../../context/ADR/ADR-003-local-execution-and-model-lifecycle.md).

## Goals / Non-Goals

Завершение серверной задачи, а не состояние соединения, определяет снятие клиентской блокировки.
Восстановление журнала и задач после перезапуска процесса не добавляется. Новых маршрутов и зависимостей нет.

## Decisions

1. Общая клиентская проверка отклоняет пробельный промпт до запросов загрузки, распознавания и проверки кеша.
   Сам промпт передаётся без обрезки, корректные пользовательские параметры сохраняются.
2. При временном разрыве сохраняется EventSource и его штатное переподключение. Ошибка соединения не вызывает
   завершение задачи. Обработчики проверяют актуальность потока и job_id. Постоянно закрытое соединение оставляет
   состояние задачи неизвестным и предлагает обновить страницу; нового OCR автоматически нет.
3. OcrWebJob сохраняет терминальный done. SSE сначала выдаёт доступные события, затем при опустевшей очереди
   завершённой задачи повторяет сохранённый итог. Это восстанавливает потерянный done без повторного OCR.
   Отдельный опрос состояния добавил бы второй протокол без необходимости.
4. Сначала снимается обработчик журналов задачи, затем освобождается активный слот, затем под блокировкой задачи
   сохраняются терминальное событие и completed, после чего публикуется done. Клиент получает завершение
   после освобождения слота; журналы нового запуска не попадают в прежнюю задачу.
5. Загрузка проверяет активный слот до чтения и повторно после await чтения. Вторая проверка и сохранение входа
   находятся под той же блокировкой, что резервирование OCR; проверка только до чтения оставляла бы гонку.

## Risks / Trade-offs

- Перезапуск сервера теряет задачи: клиент не объявляет неизвестную задачу завершённой.
- Одновременные подписки разделяют очередь журналов, но получают один и тот же сохранённый итог.
- Терминальный результат остаётся в памяти вместе с задачей; общая политика хранения не меняется.

## Проверки

Регрессии покрывают отсутствие запросов для пробельных промптов, восстановление после исправления промпта,
обрыв SSE во время OCR, оба исхода done, события прежней подписки, повторный терминальный поток и запрет загрузки при гонке.
Браузер проверяется с подставным OCR и отдельными каталогами. Реальные веса не требуются.
Очередь: [tasks.md](tasks.md).
